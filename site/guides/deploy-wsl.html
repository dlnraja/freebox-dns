Déploiement Windows / WSL2

Lab / développement seulement. Le résolveur Wi‑Fi du salon reste la VM Freebox — ne mettez jamais l'IP de ce PC dans le DHCP Freebox.

Prérequis

  • Windows 10/11 avec WSL2 activé (Ubuntu recommandé)
  • Docker Engine + Compose v2 dans WSL, ou Docker Desktop avec intégration WSL2
  • HOST_IP = IP LAN Windows visible par la Freebox (pas l'IP virtuelle WSL seule)
  • Mirrored networking Docker Desktop ou netsh interface portproxy si besoin
1

Installer Docker dans WSL2

# Dans Ubuntu WSL
sudo apt update && sudo apt install -y docker.io docker-compose-v2
sudo service docker start
sudo usermod -aG docker $USER
2

Cloner le dépôt

cd /mnt/c/Users/<vous>/Documents/freebox-dns
cp .env.example .env
# HOST_IP = IP LAN Windows (ipconfig)
3

Certificats DoH

# WSL
bash scripts/generate-certs.sh

# Ou PowerShell Windows
cd C:\Users\<vous>\Documents\freebox-dns
powershell -File .\scripts\generate-certs.ps1
4

Lancer la stack (lab)

docker compose up -d
bash scripts/health-check.sh

dig @HOST_IP -p 5356 example.com +short
curl -sk "https://HOST_IP:8453/dns-query?name=example.com&type=A"
5

Exposer les ports (si nécessaire)

Si la Freebox ne voit pas WSL directement : activez le mirroring réseau Docker Desktop, ou configurez un portproxy Windows vers l'IP WSL.

# Exemple portproxy (admin PowerShell)
netsh interface portproxy add v4tov4 listenport=5356 listenaddress=0.0.0.0 connectport=5356 connectaddress=<IP_WSL>

Alternative : Docker Desktop

Installez Docker Desktop, activez l'intégration WSL2, puis docker compose up -d depuis ce dossier (WSL ou PowerShell sur le chemin monté).

Lab vs prod LAN

En lab WSL, les ports 5356/5354 évitent de toucher au DNS système Windows. Pour prod LAN, préférez une VM Freebox ou un Pi avec docker-compose.prod.yml.
